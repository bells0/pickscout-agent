# Amazon 品类与机会研究

本 Skill 由 PickScout 维护，是市场研究入口；PickScout 完整 Agent 适配器位于 `adapters/codex/pickscout-agent/`。两者共用下列文档和模板，不各建一套流程。项目内发现链接仅指向此目录，不全局安装。

## 开始与恢复

1. 把本文件所在目录的上两级作为 PickScout 项目根；读取根目录 `AGENTS.md` 及 `docs/pickscout-sop-v1.md` 的 1.1 节。恢复任务时先读 `artifacts/research-progress.md`、当前简报、决策日志与最新报告。
2. 开展市场研究前读取 [市场研究规范](../../docs/market-research-v1.md)，按任务需要读 [研究协议](../../docs/research-protocol-v0.md)。简单状态/解释直接答，不创建空任务包。
3. 种子可以是产品、照片、ASIN、链接、类目或场景。产品入口先界定直接竞品和替代品；类目入口先拆分需求。目标不明且会改变研究时才追问，其余说明假设后推进。
4. 复用已有报告和原始资料。优先卖家精灵，功能与权限以实际可用为准；没有专门工具时用已有导出、公开页、榜单和评论，明确覆盖限制。表格与截图都接受。先列会改变当前判断的最小补数清单，不要求现有工厂、供应商或样品。

简报只维护一份当前结论区，分别写建议、用户决定、未决项、有效产物和下一动作；旧版本过程从决策日志/历史简报按需读，不并列多段“当前”。

## 研究与交付

按规范履行八步：界定市场 → 初筛方向 → 采集核对 → 需求趋势 → 竞争新品 → 关键词与买家需求 → 价格及进入条件 → 标准报告。查询顺序按信息价值动态调整，沿用当前 A/B 任务、证据和负责人，不新建常驻研究角色。

数据用于支撑专业判断。综合需求、竞争、场景、时机、投入和试错代价，给出明确倾向、优先级和推理，不用反复“待验证”或罗列未知代替结论，也不等待百分之百可靠。有合理机会依据且试错可控时，可以建议限定试验，列关键假设、投入边界、观察信号和停止/调整条件；只有足以阻断当前动作的缺口才令该动作 `insufficient`。精确数据与真实利润不编造，经验和参照推断标明依据。是否继续补数还要考虑时间和机会成本。

图案、配色、组合和定价位置等经验性建议，说明商业机制和取舍即可，不要求每条建议都有直接销量/溢价证明，也不自动前置纯色对照实验或消费者调研。把少数会改变投入的重要未知集中交代，正文交付明确选择；不能只删“尚未证明”等词而不增加专业分析。

复杂探索适合拆为独立研究、商业解释与客户审读时，主动向用户提出最小分工及收益，由用户控制是否启动与范围；已有授权直接执行，不反复确认。不默认扩张 Agent、层级、常驻角色或 worktree。分工共用本任务资料，各自回传来源/推理/反证/建议；负责人整合分歧，不按人数投票。客户审读不依赖聊天背景。

重点保护分析口径：完整自然月与近30天分开；父子体销量去重；可见新品不能推算全市场成功率；关键评论回查规格与原文；价格按用途、规格、材质和件数分组。工具估算、页面声明、自有记录、推断与假设分开。没有成本时经济性写“未评估”，不阻塞市场研究。

六维回答需求持续性、进入机会、需求缺口、流量条件、产品/价格结构与明确进入限制。逐项写支持/存在分歧/反对/未知及证据程度，不用总分或通用利润/评论数门槛决策。建议带对象和阶段，以 PickScout 的 `advance / observe / reject / insufficient` 表达。

统计排名需要同口径指标；商业推荐顺序可以用参照和专业推断综合形成，解释取舍，不以固定ASIN数阻止推荐先后。已授权的客户审读同时看事实准确、商业判断和独立可用性，不靠更谨慎的措辞或更多补数要求代替审查。

完整研究默认九章本地 HTML 主报告；具体简短比较和用户指定格式按范围缩写。使用根目录 `templates/market-scope-card.md`、`templates/source-register.csv`、`templates/market-sample.csv`、`templates/market-judgement.md`、`templates/market-research-report.html`；只复制当前需要的模板到 `artifacts/<task-id>/`，原始敏感输入到 `data/<task-id>/`。

当前有边界的建议已能有据回答、反证/限制和下一动作清楚时交付，不追求未知清零。高影响口径或来源缺口限制对应结论，仍应给出可支持的专业取舍与补证/试验方案，不填造数据。方法说明见 [一页提炼](../../docs/market-research-one-page.md)。格式检查不等于商业研究验收。

## 后续边界

市场研究支持 A/B 的研究优先级；具体供货与实物、采购经济、发货计划和上线复盘依 PickScout 对应阶段承接。市场研究产物留在 PickScout，Listing、Seller Central、FBA、库存订单和运营执行交 auto-amazon；交接报告版本、证据、未评估项、用户决定和授权状态。

继续已授权只读研究与本地分析；新增付费、外部联系、下单付款、平台写入、公开发布需具体授权。用户决定、授权与执行回执分别记录，不将研究建议自动转成经营决定。
