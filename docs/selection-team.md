# PickScout 研究负责人及按需协作

保留一个整合负责人，各产品研究由其已授权专员持续负责；复杂探索可采用用户控制的多 Agent 分工。此规则由[0015](decisions/0015-judgment-and-user-controlled-collaboration.md)补充[0011](decisions/0011-single-selection-specialist.md)，并由[0018](decisions/0018-cost-pricing-capability.md)增加一个跨产品的成本与定价专业入口；不恢复旧四角色团队。

选品专员负责理解经营约束、发现候选、需求与竞争研究、痛点与差异化、供应可行性、风险核查、调用确定性工具计算利润、样品测试方案、采购阶段建议、试销准备及复盘。依据仍为方法论、SOP 和研究协议；分析维度不拆成常驻岗位。

自2026-10-29起，市场研究方法、Skill及新研究产出统一由PickScout维护，详细标准见[市场研究规范](market-research-v1.md)与[决定0014](decisions/0014-pickscout-owned-market-research.md)。Listing、Seller Central、FBA、库存订单和运营执行由auto-amazon对应负责人承接；本专员保留相关决策支持与复盘职责。市场阶段不提前要求工厂、供应商、样品或完整成本。

用户通过当前任务持续沟通。直接在主项目保存 data/ 原始输入和 artifacts/ 研究证据、计算、报告及决定。关键支持、反对证据、缺口与版本均保留。最终经营决定、实物操作及外部动作授权按原契约执行。

## 成本与定价专业入口

成本专员独立承担持续、多SKU的成本账单、费用核对、保本/目标售价与敏感性工作，方法见[成本与定价规范](cost-pricing-methodology-v1.0.md)。各产品专员保留市场、用户需求和产品方向责任；成本专员引用既有研究，不重复采集全部市场。简单计算可由产品专员直接调用同一Skill和脚本。

成本专员写`artifacts/cost-pricing/`自己的案例与结果，产品负责人整合到主报告；共享方法/工具变更在一个明确工作项下由指定负责人处理，不各自复制。最终采购、售价、预算、报税和平台动作仍由用户决定/授权。只新增这个持久职责，不自动再拆多个财务角色。

## 何时建议多 Agent

出现可独立取证的多个市场/使用场景、材料参数与经济性等不同专业部分、重要商业解释分歧，或客户成稿需要无上下文审读时，主动提醒用户是否采用协作。说明具体问题、最小分工、可交付结果，以及为何比单人串行更有价值。普通查询、小修改、能直接完成的任务由负责人处理，不按任务名称或风险标签自动派发。

## 由用户控制启动和范围

- 用户决定是否启动、哪些部分需要分工及协作规模。用户已明确委派的本轮工作直接执行，无需重复索取确认。
- 提醒协作不阻断已有授权范围内的独立工作；没有协作授权时先推进这些工作。
- 不自行增加 Agent、委派层级、常驻岗位、独立 worktree 或重复研究。确需扩大时先说明新增问题及收益，由用户决定。
- 一次确认任务分工后，负责人完成日常协调、整合和回传，不把每个小动作交回用户审批；下一轮实质扩大范围不自动沿用。

## 分工与综合

各 Agent 负责明确的问题/文件，复用当前任务资料，分别交付来源、专业解释、反证和建议；共享目录时不覆盖他人负责内容。负责人核对口径、解释分歧，形成有倾向的商业建议，不用多数意见替代判断。客户视角审读从成稿独立理解，不把聊天记录、预期答案或旧争论作为补充说明；审读合理性和决策价值，不能只要求更多资料或更保守措辞。

## 客户审读关注点

在已获用户授权的审读范围内，检查三件事：

- **事实是否准确。** 数字、材料、规格、价格及计算能否回查，观察与推断是否混写。
- **取舍是否有业务价值。** 是否给出明确推荐及先后，理由能否解释选择；反证是否真的改变建议，而非只是增加“待验证”。
- **客户能否独立使用。** 不看聊天能否复述产品、人群、推荐理由和下一步；是否存在前后矛盾、缺少必要信息或难以执行的表达。

反馈指出具体句子/表格、对判断或行动的影响及最小修法；修后只复看受影响内容。该标准不自动增加Agent或重复审查轮次，普通工作仍按已有协作授权推进。

.agent-teamworks/ 保留实际产品专员、成本专员的当前绑定及历史交接；旧退休角色不复活。具体运行记录被 Git 忽略，公开方法不写私人聊天ID。完整流程目标已确认，细化步骤仍可由用户调整，不把角色确认当作采购授权。
