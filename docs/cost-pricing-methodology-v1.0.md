## 1. 算法总览：六步完成定价判断

目标：用已有信息和必要估算，回答**每个SKU花多少钱、多少钱保本、市场上适合卖多少、20%/30%利润率需要卖多少、多件组合是否更划算**。其中逐项费用来源、估算依据、公式与代入是重点。

| 步骤 | 做什么 | 本步产出 |
| --- | --- | --- |
| 1. 恢复事实、补齐缺项 | 先读现有产品、采购、物流、发货及市场资料；只问用户掌握且尚缺的关键事实，只估真正缺失的项 | 一份当前输入表：已知/参照/估算/未知，附来源和日期 |
| 2. 定义销售SKU | 明确单件、同尺多件、混规格组合的内容、件数、配件和包装；根据市场与费用结果调整候选 | 少量有意义的销售单元及每套组成 |
| 3. 匹配市场与费用 | 找同用途、规格、件数、品质层次的可比价格；核对相应平台费类、价格档和物流选项 | 市场候选价格带、适用计费规则和物流条件 |
| 4. 建账并计算情景 | 分通用费用/平台费用，统一币种和销售单位；按必要的物流、包规或广告情景计算 | 每个SKU、每个情景、每个候选售价的逐项账单 |
| 5. 求价格与利润 | 分档计算保本、市场候选价下收益、20%/30%参考价；多件计算每套/每条及与分开售卖的差额 | 同口径的价格与收益对照表 |
| 6. 给出取舍并交付 | 综合市场位置、费用缓冲及组合让利，明确优先比较的SKU和价位，保留最重要的反证 | 先结论、再账单和算式、最后来源及关键未知的客户报告 |

这是决策顺序，不是必须逐页完成的表单。已有答案直接复用；资料发现、市场与费用核对可按信息价值交错推进。价格跨档或输入变化时，回到受影响的计算，不重做无关工作。

固定输出四类价格：**保本价、市场推算售价、20%利润率参考价、30%利润率参考价**，并附相应每套利润和利润率。用户另有目标时替换或追加参考档；不要求用户先设利润目标，也不把20%/30%当作所有商品的进入门槛。无合理解或证据不足时说明具体范围，不能凑一个价格。

所有收益默认指**列示成本、所得税前**；利润率为利润÷售价。资料尚不完整时不叫实际净利。成本能算出底线及目标价，市场证据与专业判断决定合理候选范围，两者相互检验。

本入口聚焦定价。MOQ、交期、经营预算、现金周转等不作为默认前置问卷；其中已有且确实改变报价或分摊的条件才进入核算。研究建议不自动变成采购、发货或平台执行决定。

## 2. 输入规则：先恢复已有信息，再问、再估

先查当前研究简报、原始报价和已有测算，再按缺口读取对应物流/发货记录、价卡、账本或产品负责人资料。用户指明信息已在其他任务中时，先沿该来源找回，不重复索取或另造替代参数。

| 输入 | 必须分清 |
| --- | --- |
| 采购及包装报价 | 币种、型号、每件/每套、包含的桶/配件/税/运费；内包、外箱和标签不要重复计 |
| 产品与销售包装 | 材质、规格、件数、销售状态；裸品尺寸、完整销售包装、运输外箱各自记录 |
| 外箱与装载 | 已有标准箱规、用户给定数量/下限、该SKU装载情景、整箱毛重及其来源 |
| 平台与物流 | 站点、履约方式、适用日期、线路、区域、计费重、费档、最低费和附加覆盖 |
| 市场及比例预算 | 可比商品价格/件数/渠道/时点；广告、损失和汇损预算各自的依据与口径 |

每个输入保留**数值、单位、来源、适用对象/日期、性质**。计算工具的`actual/quoted/rule/budget/unknown/not_applicable`与报告的人话说明对应；用户确认的是箱规或数量，不自动等于确认了重量、费档或成本。

采用顺序是：**用户明确事实和适用原始记录 → 已有匹配资料/分析 → 有依据的参照或估算 → 尚无法合理估计的未知**。有运价无重量，只估重量；有箱规无运价，保留箱规再估费用。来源冲突先查对象、日期和口径，不能静默改掉事实来配合模型。

建立一份当前输入，按三层组织即可：公共资料（币种、价卡、标准箱等）、SKU定义（每套组成与销售包规）、情景变化（路线/区域、重量预算等）。各SKU引用同一套公共事实；内容、件数和重量不同的部分分别计算。100条/箱、50个双条套、全店每月100个销售单元是三个不同量。

缺资料时可按近规格、历史价卡或专业经验给有理由的区间；不把预算写成报价，不把未知当0。只突出可能改变SKU或价格判断的少数缺口，继续给有条件的专业结论。

## 3. 成本细则：通用费用、平台费用及销售单元

### 3.1 每个金额都能追溯、复算

账单按费用类型列大项，小项合并说明；**展示合并，计算依据不丢失**。每个参与计算的小项必须回答：谁收费、何时适用；原始数值/单位来自哪里；为什么采用这个估值；如何换算和分摊；包含/排除了什么。

主表保留：**费用大项｜每套金额｜来源/性质｜怎么算｜覆盖说明**。具体费率、计费基数、原始单位、日期、分摊分母和代入可放在该大项的展开明细，不把十几列全部挤到首页。

不同计费基数、触发条件和费率不能合并成一个无依据比例。综合报价无法拆开时，保留总额及覆盖范围，不造分项；新明细取得后替换同范围旧预算。适用性记已计入/已包含/不适用及理由/待确认，数值性质另记实际/报价/规则/预算。

### 3.2 A部分：通用费用

通用费用包括商品本身及平台之外的采购、准备、运输、税费、仓储、收款等支出。按实际收费方和服务边界归类：**第三方仓储放A，Amazon FBA仓储放B；供应商/第三方贴标放A，Amazon存在且适用的服务收费放B。** 同一成本只出现一次。服务用途与收费方两者都要记录，不因名称相似而重复相加。

| 费用大项 | 包含的小项 | 核算重点 |
| --- | --- | --- |
| 采购成本 | 商品、配件及报价已包含的原包装 | 对应规格单价×每套用量，统一币种；明确报价包含内容 |
| 包装与加工费 | 外袋、外箱、标签、印刷、套装固定及加工 | 按实际用量或整批分摊；已含在货款中的部分不再加 |
| 物流运输费 | 国内集货、国际头程、清关代理、末端配送及第三方订单配送 | 优先复用用户已有Excel价卡和此前分析，比较适用线路、区域、重量档与附加；按整箱计费重和装箱数量算单套费用区间，不能只给无出处的单点预留；税款单列，与Amazon物流服务防重复 |
| 税费 | 采购/出口相关税费、进口税费及所得税 | 按各自适用计税基础计算，分清已含税及有依据的调整；所得税单独说明，不能与汇损混算 |
| 第三方仓储费 | 仓租、出入库、操作及对应附加 | 按体积、重量、件数和时间计算；FBA/AWD仓储归平台部分 |
| 售后与损耗 | 退款造成的商品净损失、破损、报废、第三方退货处理及回收价值 | 按净损失或有依据的预算计；Amazon退货/退款服务费归平台部分，避免重复 |
| 收款与换汇费 | 第三方通道收费、兑换费用及汇率损耗 | 按服务报价、实际汇率或明确预算计算；若同一环节由Amazon收费则归平台部分 |
| 站外营销费 | 实际采用的站外广告、推广及相关支出 | 按实际账单或有依据的预算分摊；与Amazon广告及综合营销预算防重复 |
| 其他必要费用 | 适用的检测、认证、保险，以及已提供的摄影、软件等分摊 | 按实际服务和本品相关性合并说明；只展开适用且影响价格的部分，不默认开展整套经营调查 |

合并报价确实无法拆分时，保留一条综合费用及其已知覆盖范围，说明哪些组成项尚无法拆开；不能为了明细好看而编造分项数字。其后获得明细应替换原综合预算，而不是叠加扣款。

#### 3.3.3 合并展示与明细核算

- **主表按大项展示。** 零散、影响较小或不适用的小项可以在所属大项内概括，附适用情况，不要求每个名目单独占一行。
- **合并后仍能复算。** 实际参与计算的小项必须保留来源、数值、计费基数、公式、分摊和包含关系；可写在同一行说明或该大项的明细中。不同费率、计费基数、触发条件不能为了合并而混成一个无依据比例。
- **关键费用按需展开。** FBA配送、仓储等对价格影响大的项目，或某项附加改变保本价时，在所属大项下展开具体计算；不为排版简洁省掉重要费用。
- **覆盖范围保持完整。** 小项的名称合并展示，核查义务保留；历史名目或已停止服务按当期专项政策判断，不沿用旧费。新出现的适用项目放入对应大项并补来源。

以下项目单列核对，不能当普通正成本再扣一遍：

- **折扣与赠品**：折扣减少收入P；赠品本身及履约是实际资源支出，按项目记录。促销服务费与折扣是两回事。
- **Shipping/Giftwrap chargeback等对冲条目**：结合订单运费/礼品包装收入及对应冲销核对；平台代收后冲回的金额不能又算销售收入、又额外当成本重复扣。[S02]
- **赔付、费用返还、优惠抵扣**：与原费用分别列，核对资格、有效期及覆盖项目；尚未确认的优惠不直接冲减基准成本。赔付也不替代原损失记录。
- **收款结算预留或暂扣**：属于款项到账时点时，不把暂扣本金当一笔新增费用；若另有实际服务收费，再按账单列费。
- **历史预处理/贴标服务**：专项美国FBA Prep政策说明，自2026-01-01起新建货件不再提供原FBA预处理和单品贴标服务；不能因旧概览仍列该服务就添加旧费。实际由供应商或第三方完成的准备/贴标归A；历史货件或其他项目按其适用条件核对。[S20]

### 3.4 单位、币种、分摊和防重复

金额归一：`每套成本＝原币金额×每套用量÷分摊单位数÷每单位报告币对应的原币数量`。

- 例如预算汇率为7 CNY/USD，人民币金额除以7；保留汇率来源、日期及预算/实际属性。
- 整票/月度费用必须说明分母是箱数、销售单元数还是预计销量，以及为什么适用。不能拿总收货件数冒充已经售出的数量。
- 不同SKU混装时，按合理数量、计费重或体积分配；不能无解释地全部均摊。
- 用`covers`等覆盖说明避免重复：货款已含桶，不再加桶费；物流含税清关，不再额外扣同一笔税；共享月租不每SKU全扣一次。
- 最后列清已计确定项、已计预算、未计/未知和不适用。未知不等于0；不适用需说明理由。
- 按A/B两部分分别显示金额项小计与比例项构成，再汇总总成本。比例项在指定售价下才能显示金额，不能把百分比和美元直接相加。费用目录保持完整，实际成本只汇总适用且未被其他行覆盖的项目。

### 3.5 头程物流：按线路与整箱算区间

先使用第2节恢复的已有价卡、实箱和装载资料。有可用资料就用；没有或局部缺项再估，不先填一笔无出处预留，也不为替代已有Excel重新网页取价。历史价卡保留日期，当前适用性未确认就标条件预算。

按下列链路计算，每条候选路线各自使用其规则：

1. **确定箱和货。** 固定已有标准外箱及用户数量/下限；只估未知的本品重量、填充等。竞品单件包规若与用户箱量不一致，不能用它证明实际排布，更不能另造一个“实际外箱”。其他商品旧票的重量、件数不能迁用本品。
2. **求毛重与体积重。** `毛重＝箱内商品及销售包装重量＋外箱/填充重量`；`体积重＝运输外箱长×宽×高÷线路除数`。单位与除数匹配，FBA单件除数与国际头程分别核对。
3. **求计费重与费档。** 按该渠道的最低计费、比较与取整次序求计费重，再选单箱/整票重量档和区域单价。通常涉及`max(毛重,体积重,最低计费重)`，具体以线路为准。收寄最低实重、实际毛重与允许补足的计费重分别记录。
4. **求箱/票费用。** `运费＝按适用规则分档的计费重×单价＋适用固定费及未包含附加`。税预收、品类、Bond/保险、偏远等先核覆盖；旧票附加仅可作明示占位，不当本品税额。按方收费使用其自身公式。
5. **归一到销售单元。** `每套费用＝分配给该SKU的费用÷对应销售套数÷汇率`。同一箱100条、两条一套时分母是50套；混SKU先按合理体积/计费重等分配。不能把他票数量套过来。
6. **形成可解释情景。** 将地区、路线、装载及附加的不确定部分组合成少量可同时成立的情景，说明上下沿。跨重量档时分别算档内及边界，费用未必随重量单调增加；不能仅用“最低价×最低重、最高价×最高重”拼区间。

报告展示线路选择、每套区间、时效起止及一个完整代入例。时效按原表的自然日/工作日、开船/提取/妥投节点，不等同Amazon可售。国内集货、外箱、税费等已知金额直接用，未计部分注明；承运商运费不冒充完整到仓成本。

新运价替换同范围旧预留。物流情景传递到所有受影响SKU的保本、目标价和收益；数量改变时，箱规、重量、费档和分摊一起重核，不能只改分母。

### 3.6 多SKU与捆绑：省费与让利一起算

对适合多件销售的商品，主动比较单件、同尺多件和混规格组合。先定义每个销售套的内容、件数、配件和包装；已有组合参照优先使用。无新报价不假定采购折扣，无实测不把套装包规说成事实；缺少三条等方案资料不阻塞已有双条判断。

- **按完整销售套重算FBA。** 物理套装计一套的前提与费用档位要明确；仅两个独立SKU一起下单不自动等于该模型。展示单件分别履约费用之和、套装费用与差额，核对入库、仓储、包装等变化。
- **头程与固定费保持可比。** 同样条数的商品不因前台合售就自动少一半国际运费。比较相同内容时对齐头程、固定总费或每条分摊基准；月租总额不因订单少了就减少，不把分摊变化叫真实节省。
- **组合价来自组合市场参照。** 比较同用途、规格、件数和含桶/配件情况，不把单条价直接乘件数。低价多件竞争可能消耗履约节省，给出明确取舍。
- **同时看三种利润。** 每套利润、折每条/件利润、相同内容分开卖的合计利润。每单赚得多、每条赚得少可以同时发生；需要按用户想比较的对象解释。

在同内容、同费档、同收入比例R和对齐固定分摊的条件下：

`ΔC＝分开售卖金额成本合计－组合金额成本`

`组合利润变化＝ΔC－(1−R)×(分开售价合计－组合价)`

`保持分开售卖合计利润的组合价＝分开售价合计－ΔC÷(1−R)`

价位跨档或比例不同，改用各自的完整账单相减。阈值向上取分并代回，明确对照单价；它不是市场保证售价。每个可算SKU均列保本、市场价及收益、20%/30%参考价，优先给出费用与市场价格更协调的组合。三条等扩展可先给增量判断和条件范围，不虚构完整利润排名。

## 4. 市场价格与专业判断

先复用产品负责人或用户已有的适用资料，再补最可能改变价位的缺口；已有资料足够时不重复采集。范围聚焦定价，不自动展开完整品类研究。

按用途、材质、规格、品质、件数、包装和品牌层次判断可比性，说明差异；不要求所有属性完全一致，功能替代品也可参照。记录商品/变体、条数、渠道、日期、观察价格及优惠条件；套价÷条数只用于单位价格比较，不当成可拆卖价格。

先识别可比价位与低价替代压力，再结合本品条件提出合理候选区间。挂牌、官网、工具快照、历史价格和真实成交分清；一个高价样本不能证明我方能卖高价，也不能为了满足利润目标挑选支持样本。一般经验可以支持定位和取舍，但须说明判断理由，不包装为已测愿付价。

把候选区间交给第5节计算。若该区间下利润薄或亏损，直接说明具体SKU、价位和原因，比较价格上沿、组合或费用条件的合理调整；不靠无依据压低费用或抬高售价制造利润。无需等全部未知清零才给有条件倾向。

## 5. 统一计算、价格反推与区间

### 5.1 一套计算对象，四类价格

以`SKU k × 费用情景 s × 折后售价 P`为一个计算对象。一个情景包含可同时成立的报价、装载、物流、费档和分摊假设。所有费用先归一为每个销售单元的同一币种，按第3节保留来源和覆盖。

一般式：`J(k,s,P)＝P－Σ已计通用成本－Σ已计平台成本`。这里两类成本**不含所得税**；进口等确属商品成本的税费仍按适用口径计入。所得税有可靠金额时另列税后小计；平台代收且不属于卖家收入的买家税款不混入P。折扣先调整收入，促销服务费另计，退款与损失准备避免重复扣。

仅在同包规、同计费区间，且比例项都以同一P为基数时，将每套金额成本记为C、售价比例合计记为R：

| 计算结果 | 公式 |
| --- | --- |
| 已计总成本 | `C＋P×R` |
| 每套预计利润 | `J＝P×(1−R)−C` |
| 利润率（售价分母） | `J÷P` |
| 模型保本售价 | `C÷(1−R)` |
| 20%利润率售价 | `C÷(1−R−0.20)` |
| 30%利润率售价 | `C÷(1−R−0.30)` |
| 指定每套利润K的售价（按需） | `(C＋K)÷(1−R)` |

C为已归一的金额项，不是会计意义的固定成本。存在最低佣金、价格分档、不同计费基数或活动封顶时，先按实际规则分段，不能直接把所有费用塞进一个R。分母非正且有正成本/利润要求时，该区间没有可行解，不能生成负价或无依据结果。

市场推算价由第4节形成，按同一模型计算其利润；20%/30%是财务参考，用户无需预先设目标才可开始研究。两类价格并列，不能相互冒充。

### 5.2 分档求解与代回

1. 列出当前已计、预算、未计及不适用项。主保本包含本次已列广告预算；如另给广告前保本，名称明确区分。
2. 按有效售价费档及最低收费拐点分段求解，确认候选价仍在所用区间。跨档重算，不能沿高价费率一直推到低价。
3. 反推价向上取美分，重新代入完整账单，确认满足保本或目标利润率；同段内低一美分的适用性也要核对。若最低价恰为某段下界，不能拿其他段的费率验证它。
4. **最低可行价不代表所有更高价格都盈利。** 收费跳变会产生先盈利、跨档后亏损的区间；报告同时说明关键断点及合理候选价的实际收益。
5. 各情景反推价形成一个对应区间。若要一个售价覆盖所有所选情景，必须对这些情景逐一代回；存在跳变时按共同可行区间求解，不能机械取“各情景最低价的最大值”就认定全部达标。
6. 金额中间数保留精度；表格按分显示，利润率及差额用未取整金额计算。平台有明确逐项取整规则时按其规则；尾数价如17.99另代回计算实际利润率。

### 5.3 区间、变化与专业结论

区间来自少量有依据且内部一致的情景，不强制凑固定低/中/高三组，不将无关变量全部排列组合。价格、重量或其他费用存在分档时，检查各段及边界两侧；不默认端点包含最大/最小值，不把区间称为概率预测。

输出必须说明：区间哪一端对应什么条件，市场价格带里能留多少利润，20%/30%所需价与市场位置相差多少，哪个SKU/组合更值得比较，以及最可能改变结论的少数因素。

输入被用户纠正或新资料替换后，沿相关依赖更新：

| 改动 | 需要重核的下游 |
| --- | --- |
| 采购价、币种或汇率 | 单套金额成本、保本/目标价、利润及组合对照 |
| 套内件数或包装 | 货款用量、完整销售包规、FBA档、头程销售套数及分摊 |
| 标准箱、装载或毛重 | 体积重/实重、最低计费、重量档、附加及每套运输费用 |
| 候选售价或促销条件 | 实收收入、售价费档、佣金/活动费与对应收益 |
| 市场证据 | 候选价与判断，并重算受影响费档/利润；不反向改写报价 |

摘要、费用表、算式、目标价和SKU对照从同一轮结果生成。保留旧输入/决定作历史，当前报告只有一套有效结论；纠正一项时不只手改首页数字。

## 6. 完整演算示例（全部为合成教学数据）

以下报价、费用、广告比例、市场价格和区间选择均是假设，仅演示拆解方法，不是商品报价、Amazon费表、行业标准或真实定价建议。假设一个销售单元为一件含原包装的商品，报告币USD，预算汇率7 CNY/USD；在本例10–20美元范围内假设所有费用规则不变、无最低佣金。

### 6.2 比例项及保本推导

假设B中Amazon佣金15%、Amazon广告TACOS预算16%；A中商品净损失准备3%（不含另列平台处理费）、第三方收款汇损1%，均按P计。本例比例仅供演算，不作为其他产品的预算默认值。

`R_A＝0.03＋0.01＝0.04；R_B＝0.15＋0.16＝0.31；R＝0.04＋0.31＝0.35`

`保本价＝7÷(1−0.35)＝10.769230…美元 → 向上取分10.77美元`

复核：`10.77×0.65−7＝0.0005美元≥0`；低一美分时`10.76×0.65−7＝−0.006美元`。两者均在本例假设不变的费档内，所以10.77是本例已计口径保本价。

本例未计Amazon销售计划月费分摊、其他经营/启动分摊和所得税；其他平台条件费用的实际适用情况也没有被本例验证。10.77只解释列示项目的演算，不代表已经按3.3清单完成某个真实商品核对，也不代表覆盖全部实际成本的最终底线。真实报告不能照此省掉月费和条件费用的适用性说明。

### 6.3 市场区间如何与收益连接

为演示，假设调查得到可比商品价格12–16美元，并已基于规格和品质差异，将我方候选范围判断为13–15美元。这个选择是市场判断的假设输入，不是由7美元成本单独推出，也不是单凭算式就证明其合理。

| 假设售价USD | 佣金15% | 广告16% | 损失准备3% | 收款汇损1% | 金额项C | 原精度已计总成本 | 每套税前结余 | 结余率 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 13.00 | 1.95 | 2.08 | 0.39 | 0.13 | 7.00 | 11.55 | 1.45 | 11.15% |
| 14.00 | 2.10 | 2.24 | 0.42 | 0.14 | 7.00 | 11.90 | 2.10 | 15.00% |
| 15.00 | 2.25 | 2.40 | 0.45 | 0.15 | 7.00 | 12.25 | 2.75 | 18.33% |

由此能说明，在该组假设下，13–15美元对应每套已计税前结余1.45–2.75美元。若实际每套金额成本增加0.50美元，则各售价收益均下降0.50美元，保本升至`7.50÷0.65→11.54美元`。真实任务还需结合该变化发生的依据来判断区间是否仍适合。

## 7. 客户交付与必要核对

交付按三层阅读：

1. **先得到答案。** 每个SKU的配置、市场候选价、保本、20%/30%参考价、每套/每条利润和优先比较理由；价格必须带费用范围。
2. **能看懂怎么算。** 通用/平台费用按大项分表，小项按需展开；逐项来源、估算理由、原始单位、公式、代入和分摊保留。展开头程线路/箱重、FBA费档、保本反推及组合让利的关键算例。
3. **需要时查证据。** 来源日期和可比性、未计项及影响、历史变化可追溯；不让客户先读工具日志和全部原始表才能理解结果。

当前环境有共用报告组件时，优先复用并交付本地HTML；独立分享环境没有这些组件时，可交付包含同等结论、账单、算式和来源的Markdown或自包含HTML，不以安装额外插件为核算前提。按用户要求提供其他格式。成本报告不强制九章市场结构；同一报告原位优化、保留身份及已核内容，未定稿始终v1.0。

完成前针对本次变化核对：单位/币种/条套箱不混；覆盖不重复；费档与算式一致；组合固定费和头程比较公平；市场判断与财务目标分开；当前摘要和明细同源。需要客户审读时，以能否无背景理解结果及取舍为准，不以增加谨慎话或补数要求衡量质量。

## 8. Agent与计算工具的分工

| 责任 | 当前执行者/入口 |
| --- | --- |
| 找回既有事实、补问缺项、判断资料适用性 | 成本Agent，沿现有任务和文件来源恢复 |
| SKU候选、装箱/物流预算、费用选择、市场可比性及价格倾向 | Agent判断；已有任务计算可复用，不自动创建新角色 |
| 金额/币种/用量/分摊归一，已声明售价比例、最低额、价格档及单case反推 | `scripts/cost_pricing.py`；输入契约见项目Skill和`templates/cost-pricing-input.json` |
| 跨情景范围、共同达标价、组合公平比较、报告一致性 | Agent组织已核计算；当前脚本不自动构造装箱、市场或全部情景 |
| 最终用途、售价、采购及外部执行决定 | 用户；产品负责人继续承担完整产品/市场方向责任 |

项目唯一Skill入口：`skills/amazon-cost-pricing/SKILL.md`。真实任务调用`python3 scripts/cost_pricing.py <input.json>`；`cases`承载已准备好的SKU/情景，`prices`是待算价位，`targets`按需求提供。脚本能验证来源字段存在，不能验证报价真实性；只声明其实际支持的运算，不把未编码特殊计费方式硬塞入比例模型。

单case的`targets.margin`仅为一个目标数值；20%与30%应保持同一成本依据分别求解。`target_prices`只返回反推摘要，完整目标价账单需将所得价格放入`prices`再算，或进行等价确定性代回。`covers`检查声明标签重叠，不能自动理解“含税/含桶”的真实语义。跨情景共同达标和区间极值仍需Agent组织，不能将单case最低解当成工具已经完成全局比较。

旧`unit_economics.py`兼容历史三情景接口。旧`taxes_and_fx`须拆明含义，不根据名称认定税已计。真实输入、证据、结果和生成过程保存在被忽略的`artifacts/cost-pricing/<task-id>/`，敏感原始输入在`data/`；公开方法与教学例脱敏。

采购/广告上限、CPC、现金需求和回本时间只在用户另问时展开。技能不默认授权新增团队、跨聊天派单、付费取数、外部联系、采购付款、税务申报、物流执行、平台改价、发布或Git交付。本次优化整理方法与Skill入口，不改变计算脚本接口。
