# 一页方法：Amazon US 产品与品类研究

给 PickScout 一个产品名、照片、ASIN、链接、类目或使用场景即可开始。默认美国站、少量产品持续优化，优先用卖家精灵；表格和截图都能用。先复用已有资料，再补会改变判断的信息。市场阶段无需先提供工厂、供应商、样品或完整成本。

| 输入/步骤 | 要做的事 | 留下的结果 |
| --- | --- | --- |
| 产品或类目种子 | 确定为谁、解决什么问题、比较哪些商品 | 市场口径卡 |
| 1 界定市场 → 2 初筛方向 | 按用户任务拆分，记录保留/排除理由 | 研究优先级 |
| 3 采集核对 | 核对父子体、月份、样本、缺失与重复 | 来源和样本表 |
| 4 需求 → 5 竞争新品 | 看需求持续性、分布、竞争位置和近期进入路径 | 支持与反证 |
| 6 关键词/买家需求 → 7 价格/进入条件 | 连接搜索意图、同规格体验、现有解法与价格 | 可证伪的切入假设 |
| 8 标准报告 | 综合六维判断，列成立条件及下一验证 | 九章 HTML 主报告及明细 |

必须回答六个问题：需求持续吗；进入路径能解释吗；有具体需求缺口吗；流量条件匹配吗；产品与价格合理吗；有明确进入限制吗。每维写支持、存在分歧、反对或未知，附来源和证据程度；不靠总分或固定利润/评论数自动选品。

默认尽量取最近12个完整自然月，可扩到24个月；近30天、未完月另列。新品先观察近180天，必要时365天，核对品牌和父体背景。可见新品没有失败者分母，不能算成功率；共享评论先去重，跨规格评论不直接合并；价格先统一用途、材质、尺寸与件数。第三方估算和实际记录分清。

主报告九章：①一页决策摘要 ②范围与数据 ③需求趋势 ④细分价格 ⑤竞争新品 ⑥关键词流量 ⑦买家需求 ⑧结论与验证计划 ⑨证据附录。经济性缺完整输入就写“未评估”，不妨碍市场结论；需要经济判断时再按来源输入复算。

数据支撑明确的专业判断：更看好哪个切入、为什么现在值得、投入到哪一步，以及什么信号会使建议改变。有合理依据、试错可控时可建议限定试验，不等未知清零；只限制真正被缺口阻断的动作。继续补数的价值需与等待和错过窗口的成本比较，时间耗尽或工具不可用本身不代表研究充分。研究建议、用户采纳、采购/发布授权与执行分别记录。

复杂探索可拆分独立研究和客户审读时，负责人主动建议最小多 Agent 分工，由用户控制是否启动与范围；已有授权直接执行，普通任务不自动增加角色。

研究方法和产物由 PickScout 维护；Listing、Seller Central、FBA、库存订单与运营在 auto-amazon 执行。研究本身不授权购买、联系或发布。

可复制调用：

```text
使用 $amazon-category-opportunity-research，按 PickScout 美国站八步流程研究：____。
已有资料：____（没有也可开始）。
背景：少量产品持续经营；优先卖家精灵，表格和截图均可。
先定义细分市场和样本，复用旧证据，列最小补数清单。
核对父子体、完整自然月、可见新品偏差、同规格评论和价格。
给六维判断、支持/反证、证据程度、改变判断的条件和下一验证。
给明确优先级、商业推理、建议投入/试错边界和停止/调整条件，不等待百分之百确定。
交付九章本地 HTML 主报告；成本不全时经济性写未评估。
本轮只做市场研究。
```

详细标准见 [市场研究规范](market-research-v1.md)；完整经营阶段见 [SOP](pickscout-sop-v1.md)。规则和格式检查不代表具体商机已经验证。

若使用已安装的完整 PickScout 适配器且没有单独研究 Skill，将调用语句中的名称换成 `$pickscout-agent`，其随包规范提供相同方法。
