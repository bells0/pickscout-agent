# 0003：跨平台信号发现与三角验证

- 状态：accepted
- 日期：2026-07-31

## 背景

PickScout v0 的销售目标平台是 Amazon US FBA，但只从 Amazon 内部寻找候选，会产生两个问题：

- 只能较晚看到已经形成的需求，难以发现正在形成的使用场景和消费者问题；
- Amazon 搜索、榜单、评论和竞品页面都来自同一交易生态，多个页面不等于多个独立证据家族。

社交平台、搜索引擎、其他零售平台、众筹平台和供应平台可以补充不同阶段的信号，但它们的证明力不同。播放、点赞、收藏、榜单位置、搜索指数和供应商推荐均不能直接当作销量。

## 决策

1. Amazon US FBA 仍是 v0 的目标销售与最终竞争验证平台；候选发现和需求验证改为跨平台。
2. 研究按“信号生成机制”而不是平台数量组织：
   - 问题与注意力：Reddit、TikTok、YouTube 等；
   - 主动搜索与持续性：Google Trends、Pinterest Trends、Etsy Marketplace Insights 和其他站内搜索工具；
   - 交易或支付代理：eBay Product Research、Kickstarter 和有权使用的成交数据；
   - Amazon 竞争与可进入性：Product Opportunity Explorer、搜索结果、代表 ASIN、评论与费用；
   - 供应链与单位经济：Alibaba / 供应商报价、包装尺寸重量、FBA 费用和现金占用。
3. 社交信号只用于发现候选、消费者语言和内容表达，不单独支持 `advance`。
4. 一个候选进入下一步付费验证前，至少需要：
   - 需求判断和竞争判断分别覆盖至少两种不同信号类型，并分别来自至少两个相互独立的来源家族；
   - 需求侧至少一个关键来源不是社交讨论；
   - 所有适用硬门槛均为 `pass`，不存在 `unknown`、未解决的 `hard_gate` 或 `status_change` 缺口；
   - 单位经济全部必填输入有来源，悲观、基准和乐观情景已由确定性工具完成；
   - 对可能为短期热点的信号进行至少两次时间切片，通常间隔约 7 天。
5. 每条证据继续记录 `independence_basis.upstream_origin`。多个工具如果复用同一上游数据、榜单、热视频或报告，只按一个上游证据处理。
6. Temu、AliExpress 和 Alibaba 的公开榜单或推荐位默认用于价格压力、同质化和供应可得性判断，不当作美国消费者真实销量；只有取得口径清晰且有权使用的交易数据后，才升级为交易证据。
7. 付费数据、账号授权、API 接入或数据导出仍需用户确认；公开、低成本、可逆的发现研究可直接进行。

## 建议状态的最低证据门槛

| 状态 | 最低要求 |
| --- | --- |
| `advance` | 所有适用硬门槛均 `pass` 且无 `unknown`；需求和竞争分别覆盖至少两种信号类型与两个独立来源家族；需求侧至少一个关键来源不是社交讨论；三情景单位经济已复算；短期趋势已复查 |
| `observe` | 有需求线索且无明确否决项，但持续性、交易、竞争或供应证据仍不足 |
| `reject` | 任一决定性合规、现金、MOQ、利润或竞争门槛失败，或热点无法获得独立复核 |
| `insufficient` | 证据表面很多但去重后不足，或缺少会改变状态的报价、尺寸重量、费用、交易或美国市场证据 |

`advance` 只表示进入下一项低成本验证，不表示采购或上架。

## 不采用的方案

### 只看 Amazon

不采用。它适合验证当前需求、竞争和费用，但不足以发现早期问题、站外兴趣和跨平台价格压力。

### 按平台数量投票

不采用。TikTok、Instagram、YouTube 和媒体文章可能都在复述同一个上游事件，平台数量不能代表证据独立性。

### 用社交热度生成综合机会分

不采用。互动量受到推荐算法、达人投放、刷量、内容形式和人群结构影响，与购买意愿和可盈利性没有稳定的一一对应关系。

## 影响与后续动作

- 后续开放式选品先做跨平台候选发现，再进入 Amazon 和供应链验证。
- 研究报告需要明确区分注意力、主动搜索、交易、竞争和供应证据。
- 对热视频或突发趋势默认安排第二次时间切片。
- 首个试点将对“超细纤维健身 / 旅行毛巾、宠物梳毛手套、成人艺术工具袋”执行同一套跨平台脉冲扫描，以比较该框架是否真正改变候选顺序。
