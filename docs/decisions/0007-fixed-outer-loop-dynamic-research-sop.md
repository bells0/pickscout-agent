# 0007：固定外层决策循环与动态研究内环

- 状态：accepted
- 日期：2026-08-13
- 后续：关于不创建可分发 Agent 兼容包的部分已由 [0008](0008-publish-distributable-pickscout-agent.md) 取代；固定外环、动态内环的决策继续有效。

## 背景

PickScout 已通过真实任务验证了证据优先、跨平台三角验证、决策留痕和阶段性买样等原则，但方法分散在 PRD、研究协议、决策记录和任务经验中。其他使用者难以知道从哪里开始、每一步要产出什么；Agent 也容易在长任务中出现阶段混用、过早排序、过度追问或恢复成本过高。

用户要求把现有经验沉淀为固定方法论和可跟随的操作步骤，并让后续 Agent 自动使用。

## 决策

1. 新增 `docs/pickscout-methodology-v1.md`，作为稳定的方法论层，定义决策阶梯、最低证据包、证据三角验证、阶段建议、授权边界和质量护栏。
2. 新增 `docs/pickscout-sop-v1.md`，作为人和 Agent 均可执行的标准操作程序。
3. 新增 `templates/task-run-checklist.md`，真实任务开始或恢复时复制到任务目录，用于固定外层运行循环和交接检查。
4. 根目录 `AGENTS.md` 必须将方法论和 SOP 列为项目事实来源，并要求真实任务按 SOP 执行。
5. 固定的是外层决策循环、阶段门槛、记录和授权；研究关键词、来源和工具顺序继续由 Agent 按信息价值动态决定。
6. `advance / observe / reject / insufficient` 必须带明确对象和阶段。样品建议、量产门槛、FBA 发货状态和外部动作授权不得合并成一个状态。
7. 不创建仓库 Skill 子包，不安装用户级能力，不开发固定页面向导或工作流引擎。

## 备选方案

### 只扩写研究协议

不采用。研究协议负责证据义务和充分性，若同时承担人员操作、阶段执行和交接，会过于庞大且不利于快速使用。

### 创建 PickScout Skill

不采用。当前仓库本身就是运行和调试边界，增加 Skill 子包会重新引入已经否决的第二层产品边界。

### 固定每个来源和工具的执行顺序

不采用。不同候选的最高价值未知项不同，机械顺序会增加低价值工作并削弱 Agent 判断。

## 影响

- 新使用者可以按 SOP 和运行清单开展任务，不需要阅读全部历史线程。
- Agent 恢复任务时有固定入口和交接字段。
- 项目同时保留可重复性与动态研究能力。
- 后续可为方法论入口、阶段字段和运行清单增加自动化契约测试。
