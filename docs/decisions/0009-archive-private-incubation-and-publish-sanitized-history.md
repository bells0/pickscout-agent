# 0009：归档私有孵化仓库并发布脱敏历史

- 状态：accepted
- 日期：2026-08-18

## 背景

PickScout Agent 的私有孵化仓库同时保存了两类内容：可开源的方法论、模板、脚本与 Agent 适配器，以及只属于首位用户的线程索引、候选、供应商、采购、物流和执行复盘。直接把原仓库改为公开会使后者及其 Git 历史一并公开；只删除当前文件也不能清除旧提交中的内容。

用户要求保留项目演进历史、建立新旧项目之间的联系，并且以后只维护一个活跃仓库。用户同时明确：项目本体是 PickScout Agent 选品助手，当前 Skill 机制只是可替换的时代性适配器。

## 决策

1. 原始仓库改名为 `pickscout-agent-private-archive`，保持 Private，并在迁移完成后归档为只读；它保存完整原始 commit hash、内部记录和孵化历史。
2. 新建公开仓库 `pickscout-agent`，作为唯一活跃维护仓库。
3. 公开仓库从原始历史生成脱敏历史，保留公开文件的提交顺序、作者、时间、说明和演进关系；因为删除了私有内容，受影响的 commit hash 必然重写。
4. 公开历史排除线程 ID、具体候选与 offer、用户经营计划、采购数量、物流账户与核价过程、Agent 执行复盘，以及其他只属于私有试点的内容。
5. 公开仓库可以保留或重新加入经过泛化的产品文档和决策记录，但不得以个人测试记录作为公开产品事实。
6. 公开仓库使用 Apache License 2.0。
7. PickScout Agent 的长期核心继续位于根目录的方法论、协议、模板和确定性工具；`adapters/codex/pickscout-agent/` 只是当前 Codex 兼容层。
8. 迁移完成后，本地活跃工作区的 `origin` 指向公开仓库；私有归档只作为历史恢复来源，不再进行日常开发。

## 公开历史最低审计

公开前必须同时满足：

- 对公开分支所有 commit 和 blob 做私有标识与凭据模式检查；
- 不存在 `artifacts/`、`data/`、线程总结、内部计划或具体候选执行记录；
- Apache-2.0 正文存在；
- 项目完整回归通过；
- 从公开 GitHub 路径由 Agent 安装 PickScout Agent，并核对安装目录与发布适配器一致；
- 新公开仓库确认是 Public，旧仓库确认是 Private 且 Archived。

## 影响

- 私有原始历史与公开协作历史同时保留，但用途不同。
- 公开仓库只维护 PickScout Agent 的通用产品能力，个人研究继续保存在被 Git 忽略的运行产物中。
- 未来 Codex 不再使用 Skill 机制时，只需替换适配器，不迁移产品身份与核心方法。
