# 0013：按需读取外部品类研究 Skill，保留完整选品流程

- 状态：accepted
- 日期：2026-10-19
- 用户决定：将 PickScout 与既有品类研究 Skill 在本地实际接入，按需复用，保留完整选品流程，避免重复维护；不全局安装。

## 决策

PickScout 继续拥有 A–G 阶段、模板、确定性计算和用户决定记录。品类、竞品、趋势、关键词与需求研究按 SOP 第 1.1 节读取可用的 `amazon-category-opportunity-research`，同一负责人复用当前任务和原始证据。

品类研究正文只在源 Skill 维护，PickScout 只维护接入规则。工作区可用项目内目录链接暴露该 Skill；本机链接被 Git 忽略，公开适配器不包含私人路径或该外部 Skill 的副本。适配器通过已镜像的 SOP 使用相同接入规则。

该能力为可选项：外部 Skill 不可用时，PickScout 继续使用自带方法论和协议。既有选品门槛、计算、授权及完整流程不因接入而改变；研究优先级不直接等同于 PickScout 阶段通过。

## 选择理由

单纯介绍职责不能让 PickScout 读取方法；复制正文会产生第二个维护源；将外部 Skill 变成必需依赖则会破坏现有自包含分发。可选读取加本地目录链接满足当前复用需求，不新增运行框架、配置服务或助手。

## 验证与边界

检查实际目录链接能否读到源 Skill 的同一文件，运行现有分发包及研究契约检查，确认 SOP 镜像和原有流程保持一致。文件接入与契约检查不等于新会话的自动选择或实际商业研究已经验收；真实市场结论仍需对应来源和研究任务验证。
