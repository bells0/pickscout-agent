# 0018 成本与定价独立能力，共用 PickScout 方法与计算

- 状态：accepted。
- 日期：2026-11-03。
- 方法版本：v1.0未定稿；共享不代表方法最终定稿。

## 问题

跨产品需要持续进行逐项成本、销售套装、物流区间、保本及利润率定价。单一三情景金额表不能完整表达币种/用量/分摊、售价比例、最低费用和售价档位，也容易把未计税费的结余误称净利。

## 决策

1. 成本与定价作为可独立调用的专业入口，唯一维护源为本仓`skills/amazon-cost-pricing/`、`docs/cost-pricing-methodology-v1.0.md`和共用计算工具。产品负责人继续完整品类研究与产品方向，成本入口可补充定价所需的市场参照。
2. 六步主流程为恢复事实、定义SKU、匹配市场/费用、建账与情景、价格求解、判断交付。先复用已有报价、物流价卡、箱规和通用耗材成本；只估缺项，不以Agent假设覆盖用户事实。
3. 费用分通用与平台两部分，大项展示、小项可追溯。逐项来源、日期、单位、估计依据、分摊、覆盖和算式保留，未知不视为0。
4. 头程按各线路的箱规、毛重/体积重、最低计费、重量档和附加计算，再分摊到销售单元。条、套、箱与月销量分开，重量和价格跳档不假定单调。
5. 单件、多件和混规格SKU分别核算完整销售包装。组合比较对齐实物内容、头程和固定分摊，区分每套、每条及分开销售合计利润；固定月费不会因少几个订单而降低。
6. 并列市场推算价、保本和20%/30%等利润率参考价；利润率以售价为分母，财务反推不替代市场接受判断。所得税从税前经营合计中分离，成本覆盖不足不称完整净利。
7. 新工具`scripts/cost_pricing.py`负责已声明成本、价格档及目标的确定性计算；旧`unit_economics.py`保持兼容并共用汇总核心。Agent负责来源适用性、装箱/物流准备、市场判断和跨情景比较，不把工具描述成全自动经营系统。
8. 当前完整Codex适配器仍在`adapters/codex/pickscout-agent/`并与源文件同步；独立成本Skill分享包由导出工具从明确的源文件清单生成，包含计算依赖、方法、合成输入、许可和来源说明。生成物不作为第二维护源，也不安装到用户级目录。
9. 经用户对具体目标仓库授权，可将该生成包作为组织共享快照备份。auto-amazon中的成本Skill快照只用于共享与调用，记录上游提交，更新从PickScout重新导出；不改变完整市场研究归属，不扩张运营或外部动作权限。
10. Git交付采用隔离任务分支、限定文件提交、验证后推送和PR；合并与可见性变更仍需明确授权。真实研究报告另作用户指定的分享产物，不随公共源码上传。

## 验证与边界

- 验证币种/套数/分摊、最低费用、价格跳档、20%/30%反推、未知及重复覆盖；运行确定性工具回归与适配器契约检查。
- 独立包从干净目录解包并实际运行计算器，确保不依赖原仓库路径或私有数据。包内示例仅作合成演算，不是报价或长期费率。
- 公开方法和代码脱敏；真实报价、用户资料、团队绑定和运行复盘保留在被忽略的本地目录。
- 角色是工作入口而非执行授权；不自动创建新角色、询价、采购、付款、报税、改价、发货或公开报告。
