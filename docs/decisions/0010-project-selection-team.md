# 0010：项目内选品团队

- 状态：superseded（由 0011-single-selection-specialist.md 取代；以下保留旧方案历史）
- 日期：2026-09-10

## 问题与结果

选品的市场证据、供应成本和风险验证具有持续且可独立开展的职责。单一对话入口需要把这些工作交接、整合并恢复，同时保持原有阶段与用户决定边界。

采用一名统筹和三名专业角色，职责见 [选品团队](../selection-team.md)。用户继续面对一个统筹入口；专业角色按明确任务取证与返回，统筹负责共享证据、阶段结论和决定记录。

## 决策与边界

- 按用户明确要求，以侧栏平级、持久的独立任务承载专业角色，复用宿主任务通信和已安装 Agent Teamworks 协议，不建设编排服务。
- 团队负责研究与决策支持，用户保留最终决定和外部动作授权。
- 持久角色与临时运行绑定分开；启动检查不能冒充真实市场研究验收。
- 现场 `.agent-teamworks/` 全部 Git 忽略，遵守 0009 对线程索引和私有执行记录的限制；通用规则进入 `docs/`，真实研究继续进入 `artifacts/` 与 `data/`。
- 不修改兼容适配器的自包含规则，不把本机团队绑定分发给其他使用者。

## 验证方式

实际创建平级可见成员任务，检查其读取、产出、回传统筹和整合；核对 Team/Role/Work Item/Decision 记录结构、绑定与写入边界；检查私有运行记录未进入 Git，运行现有契约与回归测试。

本轮不以虚构商品证明效果。真实选品协作仍需后续有具体种子、真实来源和计算输入的任务验证。接入结果保存在私有现场记录中。
