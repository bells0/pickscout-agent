# Amazon 成本与定价

本技能唯一维护源在PickScout的根`skills/amazon-cost-pricing/`；读取同仓[成本与定价方法](../../docs/cost-pricing-methodology-v1.0.md)。与品类研究共用证据和计算，不另写一套收费算法或硬编码长期费率。

## 执行

新产品定价按下面六步组织；局部追问或输入修正只执行相关环节，复用其余已核内容。

1. **恢复事实，再补缺项。** 读当前简报、报价、物流价卡、发货箱规及通用耗材成本；用户指出资料在其他任务时先找回对应记录。已知事实优先，未知部分才问或估，不重复索取或另造箱规。按公共资料、SKU定义、情景变化组织输入，保留来源、日期、单位和性质。
2. **定义销售SKU。** 明确每套规格、件数、桶/配件及包装；适用时比较单件、同规格多件与混规格。条/件、销售套、箱和月销量分开，不先要求用户已有完整方案或利润目标。
3. **匹配市场与费用。** 复用适用的市场资料形成可比价带，核对该SKU费类、价格档和线路条件；只补影响定价的缺口。已有物流Excel足够时直接用，不为形式刷新网页。不同渠道、变体、件数及观察时点分清，挂牌不称成交。
4. **建账和情景。** 按方法第3节分通用/平台费用，大项展示、明细可复算。头程从真实标准箱、装载和该线路计费规则算到每套，少量可同时成立的情景形成区间；FBA按完整销售套独立匹配。固定月费不因捆绑减少，已含项目不重复，未知不填0。
5. **调用工具求价。** 用`../../scripts/cost_pricing.py`计算逐价账单、保本及20%/30%等参考价，按方法第5节复核费档与代回。成本比例只在相同计费基础和有效分段内合并；跨重量/售价档不假定单调。组合按同内容对照每套、每条及两单合计利润，核对让利是否吃掉节省。
6. **判断、交付与联动。** 保留市场推算价和财务目标价的区别，明确SKU/价位倾向、最强反证及关键未知。结果落`artifacts/cost-pricing/<task-id>/`，摘要→通用/平台账单与算式→来源分层阅读；默认共用HTML，按要求其他格式。输入变更后重建受影响case及全部关联展示，保持一个当前结论入口；未定稿方法继续v1.0。

所得税从税前经营成本中单独分离；进口等商品成本税按适用口径计入。完整税务和成本未确认时不称税后净利。MOQ、交期、经营预算和现金计划不作为定价前置问卷；广告/采购上限等扩展仅在相关问题需要时使用。

## 当前工具边界

- `cases`提交的是Agent已经准备好的SKU/情景成本。工具不自动调查市场、查费表、构造装箱或确定报价真实性；字段有来源不代表来源已被验证。公共[输入例](../../templates/cost-pricing-input.json)为合成结构示例，不是现实费率。
- 单case的`targets.margin`是一个数值；20%与30%需在同一成本依据上分别求解，例如复制case后只改目标，或分次调用。输出`target_prices`不是所求价的完整账单；需将候选价加入`prices`再次计算，或作等价确定性代回。
- 价格档与最低额可以声明；封顶、累进或非售价计费基础是否能准确表达，先核输入模型，不能声称任意收费函数已自动支持。`covers`只检查声明标签重叠，真实覆盖关系仍由Agent判断。
- 最低反推价不保证所有更高价都达标。跨情景要一个共同达标价时，逐情景代回，必要时求共同有效区间；当前工具不自动完成这种合并。旧`unit_economics.py`保留兼容，不改写历史结果。

## 输入契约（v1）

- 顶层`market/currency/as_of/selling_unit`、`currency_per_reporting_unit`（原币/1报告币，含source/as_of）、`cases`。
- 每个case包含`id`、`costs`、`prices`和可选`targets`、`price_bands`。案例是SKU/包装/情景的明确定义，不要求固定三个。
- 成本行：`id,label,category,kind,value,status,source,as_of`。金额均为十进制字符串。`kind=amount`以`currency,quantity,allocation_units`归一；`kind=rate`为售价比例，可有报告币`minimum_amount`。`status=actual/quoted/rule/budget/unknown/not_applicable`；未知value为null并给reason，不适用也给reason。`covers`可列多个覆盖项。
- 默认检查的类别：`product,packaging,inbound,import_duty,placement,fulfillment,storage,referral,advertising,losses,fx,overhead,launch,income_tax`。缺少或未知类别只产生覆盖缺口，不伪造成0元或阻止已计口径预算。
- `prices`每项含`value/status/source/as_of`；v1售价按0.01递增，费用中间值保留完整精度。`price_bands`使用`min_price`（含）和`max_price_exclusive`（不含，null为无上限），`overrides`按成本id覆盖value等已声明参数，仍附source/as_of/status。不填档位代表只声明静态费用模型，不代表已掌握所有售价规则。
- `targets.unit_profit`与`targets.margin`分别反推，不相加；margin以售价为分母。所有反推为列示成本口径的经营结余、所得税前。所得税仅接受已明确的每套金额分摊行，不根据一个假设税率自动推完整净利。
- 输出包含`scope`缺口、每个价格的明细/结余及所得税分摊后小计、反推结果与适用档位。税后小计仍不等于完整净利，必须连覆盖情况阅读。未知、无适用档位、无可行解分别说明。

## 分工与授权

成本专员是用户直接咨询的同级入口；品类负责人仍负责市场与产品推荐。简单问题可就地调用此技能，批量/持续模型可交给成本专员。跨聊天消息遵守宿主和用户授权；技能本身不授权发消息、创建更多角色或改变别人的报告。

不默认扩展到报销记账、税务申报、采购付款、价格后台修改、物流发货和公开发布。1688若用户禁止直接访问，遵守其指定采集路径；没有数据不能绕过限制。
