# 0016：推荐顺序 当前结论与客户审读的执行收敛

- 状态：accepted
- 日期：2026-10-31
- 补充：0015的商业判断与协作原则。
- 用户明确采纳：澄清排序性质、只保留一个当前结论区、调整客户审读标准三项改进。
- 本次范围之外：用户提出的阶段区分暂为想法，不作为此次新增规则，不新增或细化阶段划分。

## 原因

方法仍使用含义不清的“严格排序”并与固定ASIN数量相连，容易限制专业推荐。任务简报将多个旧版本标为“当前”叠在一起，恢复时会误读。客户审查也可能只追求更谨慎或更多证明，忽略是否帮助客户作选择。

## 采纳的三项改进

1. **排序性质明确。** 统计排名按同口径数据和计算；商业推荐顺序按需求、竞争、成本、时机和用户条件综合判断，解释取舍。固定ASIN数不作为给商业推荐的门槛，专业顺序也不能冒充销量榜或成功率。
2. **当前结论唯一。** 简报只有一份当前结论区，包含建议、用户决定、未决项、有效产物和下一动作。旧判断与过程移入决策日志或历史简报，保留历史但不并列多个恢复入口。
3. **审查客户价值。** 已授权的审读同时看事实准确、商业取舍、独立理解和行动清晰度。反馈说明具体问题、影响与最小修法；修后复看受影响部分，不以谨慎用词、补数数量或格式通过代替质量。

## 落实与边界

同步根契约、方法/SOP、研究Skill、相关模板及分发镜像；整理既有任务简报，使旧版本留在历史文件，私人实例不进入公开方法。既有数据和计算真实性、用户决定及外部动作授权不变。此次不调整产品参数、打样数量、经营选择，不启动额外Agent或建立新的审批/评分机制。

用现有研究与分发契约检查文档接入和镜像一致性；核对本次简报只有一个当前结论区、旧稿完整保留及有效交付链接。后续实际报告仍需由用户判断这些改动是否改善业务价值，文档检查不代表已经验证经营效果。
