# 0015：不确定性下的专业判断与用户控制的协作

- 状态：accepted
- 日期：2026-10-30
- 补充：0012 商业判断优先；部分取代0011单 Agent 默认，不恢复0010旧常驻团队。
- 用户决定：市场数据应支撑专业业务判断；不等待百分之百可靠、资料全部齐备才给方向结论。复杂探索适合多 Agent 分工，但由用户控制启动和范围，负责人应提醒适用场景，不一刀切自动派发。

## 问题

实际研究虽有大量数据，建议却不断退回“尚待验证”。旧协议将任何可能改变建议的开放缺口都视为不能交付，导致等待、失去时机以及把判断退回用户。单 Agent 包揽复杂探索也可能沿既有解释继续偏移；自动扩张团队则会增加重复和协调成本。

## 决定

1. **给出专业取舍。** 连起数据、商业解释和行动，明确更看好哪个方向、为什么、当下值得投入到哪一步。保留反证和关键假设，不以这些内容取代判断，也不保证成功。
2. **证据匹配投入。** 方向探索与可控试验不需要量产级证明。有合理机会依据且损失可限定时，可以建议推进；给试错边界、观察信号和停止/调整条件。等待和错过窗口的成本参与比较。
3. **缺口限定到动作。** 真正阻断当前动作的未知才使该动作`insufficient`。可通过试验管理的假设继续开放，仍可给当前最佳建议；不假装事实齐全，不伪造指标、报价、厚度、预算或利润。情景假设和真实输入分别标识。
4. **复杂任务按需协作。** 跨场景、独立研究部分、重要解释分歧及客户成稿审读是可提醒的场景。负责人建议最小分工及收益，由用户决定启动与范围；明确授权后直接协调完成，不重复确认，也不自行扩大 Agent、层级、常驻岗位或 worktree。
5. **综合而非投票。** 各部分返回来源、推理、反证和建议，由一个负责人解决口径与商业分歧。客户审读从成稿理解价值和逻辑，不凭聊天补足内容，不能仅通过增加保守措辞来“通过”。

## 边界与落实

证据真实性、可复算公式、用户最终决策及外部动作授权保持。该规范调整本身不选择具体产品用途、参数、SKU、采购或预算，不自动启动多 Agent 团队。

更新项目契约、方法论、SOP、研究协议、市场研究规范、项目 Skill、关键报告模板及分发镜像。保留0011/0012历史并标明后续调整。不改用户级 Skill、插件、配置或其他仓库。

验证用现有研究契约与分发一致性检查，另核对旧“任何状态变化缺口都阻断”规则是否清除。下一次真实复杂研究检验能否给出有依据的明确建议和受控分工；文档检查不冒充业务效果已经验证。

## 2026-10-31 实施补充

用户再次指出客户报告的图案建议被“尚未证明更受欢迎/有溢价”和前置对照要求淹没。经验性设计、配色、组合、定位与价格位置可以用商业机制形成明确推荐，无需每条先获得直接转化实验。把影响投入的少数未知集中说明；落实到客户正文和建议表，不仅修改规范或替换保守词。事实中的缺失、真实报价和实际利润仍如实保留。
