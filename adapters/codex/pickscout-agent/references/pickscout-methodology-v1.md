- 状态：accepted

- 适用范围：Amazon US FBA 个人卖家的商机发现、候选研究、买样、采购前验证和首票物流决策

## 1. 方法论目标

PickScout 把市场数据转化为及时、有取舍的专业判断，帮助用户发现机会、选择切入点，并以可控代价逐步验证。证据、推理、情景计算和后续结果可追溯；最终经营决定与外部动作由用户授权。

方法论固定以下内容：

- 外层决策循环；
- 每个经营阶段的输入、门槛和输出；
- 证据、计算、建议与用户决定的分离方式；
- 暂停、恢复、执行授权和留痕要求。

方法论不固定搜索关键词、平台顺序或工具编排。Agent 仍应根据当前未知项的信息价值动态选择研究路径。

## 1.1 首要选品原则

以下原则约束后续方法、SOP、证据要求和模板的解释；用户当前明确指令优先。流程服务于经营判断，不得反过来制造无关的筛选条件。

1. **先回答商业问题。** 围绕需求（谁买、为什么买、真实信号）、竞争与进入空间（现有供给、售价、进入机会）、经济与供给（采购成本、尺寸重量、费用与售价空间、货源选择）、用户选择（选项、利弊、建议优先级）展开研究。
2. **适合卖，不必复刻或创新。** 竞品的袋数、隔层、材质、颜色和结构是比较属性，不自动成为候选准入条件。允许比较满足同一需求的不同形态，注明规格与价格差异；不要求完全同款、结构创新、定制或独占差异才能继续评估现货。
3. **按阶段投入精力。** 初步选品先判断方向和候选的商业潜力，不提前要求买样、质检或采购阶段的完整资料。耐用测试、满载视频、定制细节和缺陷协商等留到相关阶段；只有已有证据表明某风险会改变当前判断时，才提前核查。
4. **只补会改变决定的信息。** 补充资料前先问：它是否可能改变“值不值得做、哪个优先、投入多少”？不能说明影响的细节不阻塞推进。资料未齐仍可展示初步选项、比较和有条件建议；非关键缺口不自动触发淘汰或整体 `insufficient`。统计排名、最终通过结论和采购判断仍须相应证据。
5. **整合选项，用户决策。** 合适的品类方向可以继续寻找多个产品和供应商。单一供应商或一次高报价不能代表整个品类；充分利用用户已有工具及获准来源，区分同款与功能替代品，整理成本、条件、利弊及建议，由用户判断是否采纳。不得把 Agent 偏好自动变成用户决定或淘汰规则。
6. **保留真正必要的严谨。** 硬门槛只来自用户明确约束，或有依据且适用于当前阶段的法律、安全、知识产权或商业否决风险。事实、推断、假设、估算与建议分开；不编造缺失数值，不把初筛估算说成已验证利润。采购、付款、发布等外部动作仍需独立授权。
7. **交付专业判断。** 数据为判断提供依据，Agent 应结合需求、竞争、使用场景、商业时机和经营条件解释“更看好哪个、为什么、现在值得做到哪一步”。合理推断不必等同于已发生事实，也不要求百分之百可靠；不得只罗列缺口，把取舍全部退回用户。

## 1.2 不确定条件下的行动建议

- **按动作确定证据强度。** 发现方向、比较方案、低成本试验、量产投入和履约动作需要不同程度的把握。证据强度与现金、不可逆性、失败损失相称，不把量产的证明要求前置到机会探索。
- **形成当前最佳选择。** 在可比较的选项间给出倾向与优先级，连起“已知信号→专业解释→建议动作”，说明最强反证及为何当前仍值得或不值得做。数据有限时可用商业经验和邻近案例推断，注明可迁移理由和差异，不把它们冒充直接销量或成功保证。
- **把未知转成试验。** 有合理机会依据、没有已知否决且试错可控时，可建议限定范围的小步试验。写明关键假设、投入上限或待用户选择的投入范围、观察信号和停止/调整条件。不能为了给出行动而虚构预算或实际报价。
- **区分阻断与可管理未知。** 足以使当前动作缺乏合理依据、或损失无法限定的未知，才对该动作记为 `insufficient`。可由试验检验的假设保留在建议中；未来可能推翻判断，不等于现在必须继续无限搜集。
- **计算等待的代价。** 比较新增信息的预期价值、取得时间与成本，以及错过窗口、推迟学习和延迟试验的成本。新增资料主要只提高确信、很难改变当前可逆动作时，停止补数并交付建议。

专业推断、情景假设和已核实事实分栏；精确市场指标、报价、费用、厚度或利润不允许靠经验补成事实。可用有出处的参照和明确假设做区间/敏感性测算，说明适用范围，不宣称已验证利润。建议小步试验不等于执行采购或发起平台动作。

## 2. 核心模型：固定外环，动态内环

```text
确认当前决定与阶段
  → 建立可恢复任务
  → 定义阶段门槛
  → 建立最低可比证据包
  → 循环解决最高价值未知项
  → 调用确定性计算与校验
  → 形成阶段建议
  → 用户决定或授权
  → 留痕、执行、暂停或进入下一阶段
```

外环固定，是为了让任何人都能恢复和审计。内环动态，是为了避免为了走流程而搜集低价值资料。

市场研究的 A–B 内环统一执行 [八步研究规范](market-research-v1.md)：界定市场、初筛方向、采集核对、需求趋势、竞争新品、关键词与买家需求、价格及进入条件、标准报告。六维判断与九章报告以该规范为唯一详细定义；查询顺序仍按信息价值调整。

PickScout 维护市场研究方法、证据和研究报告。auto-amazon 承接 Listing、Seller Central、FBA、库存订单与运营执行；本方法的 F/G 保留决策支持和复盘接口，不将研究建议转成自动平台操作。

## 3. 五个必须分开的对象

### 3.1 事实

来源直接支持的观察，例如某个 ASIN 在某日显示的价格、评价数或购买标签。

### 3.2 推断与假设

- 推断：由事实和明确规则得出的解释。
- 假设：尚未充分验证、可能改变建议的前提。

### 3.3 Agent 阶段建议

只使用：`advance`、`observe`、`reject`、`insufficient`。

建议必须写明所针对的对象和阶段，例如：

- 候选研究阶段：`advance` 到样品验证；
- 量产采购阶段：`insufficient`；
- FBA 发货阶段：`insufficient`。

不得只写一个没有阶段的 `advance`。

### 3.4 用户决定

用户可以选择继续、观察、放弃或暂不决定。Agent 建议不能自动变成用户决定。

### 3.5 外部动作授权与执行事实

“同意继续研究”“批准进入买样队列”“授权下单”“已经付款”是四件不同的事。每个外部动作必须分别记录：

- 是否需要授权；
- 用户是否明确授权；
- 动作是否实际执行；
- 执行结果和证据。

## 4. 决策阶梯与阶段门槛

每个任务只处理当前需要回答的阶段。阶段可以跳过不适用项，但不能把后续阶段的门槛冒充当前已经完成。

| 阶段 | 核心问题 | 最低输入 | 允许输出 | 不代表什么 |
| --- | --- | --- | --- | --- |
| A 候选发现 | 哪些问题或产品形态值得进入同口径研究？ | 用户种子、市场、经营边界 | 候选池、发现假设、研究优先级 | 不代表类目推荐或采购建议 |
| B 候选筛选 | 哪些候选值得投入下一轮验证？ | 最低可比证据包 | `advance / observe / reject / insufficient` | `advance` 不代表买样或采购 |
| C 样品筛选 | 哪个具体产品和供应来源值得买样？ | 具体 offer/SKU、页面条件、关键风险 | 样品建议、测试计划、待授权动作 | 不代表量产工厂或 FBA 可行 |
| D 样品验证 | 实物是否通过产品和包装测试？ | 样品、测试计划、实测记录 | 通过、整改、复测或淘汰建议 | 不代表单位经济已通过 |
| E 采购与单位经济 | 是否值得按某数量量产？ | 实测包装、正式 RFQ、官方费用、头程、情景输入 | 可复算门槛结果与采购建议 | 不代表已经下单或付款 |
| F FBA 与首票物流 | 发多少、发到哪里、选哪条路线？ | FBA SKU、实际 FC、封箱实测、合规资料、书面全包价 | 发货数量与物流建议 | 不代表已创建货件或订舱 |
| G 上线复盘 | 真实结果是否支持补货、调整或停止？ | 订单、转化、广告、退货、库存和利润 | 补货、观察、整改或退出建议 | 不自动修改全局评分模型 |

## 5. 最低可比证据包

先区分两种排序：

- **统计排名**按销量、价格、增长等指标排序，需要可比较的定义、样本、时间和计算；数量不足或口径不一致时，只报告可支持的范围，不冒充完整市场排名。
- **商业推荐顺序**由需求、竞争、场景适配、成本、时机及用户条件综合判断。证据有限时仍可明确推荐先后，说明主要依据、取舍和改变建议的信号；不要求先凑齐固定数量的同款ASIN。

下列证据包用于帮助发现缺口、判断可比性，不是商业推荐的统一准入清单。比较以需求与用途为中心，不要求结构完全相同；规格、价格带或形态不同须解释差异，不能把专业推荐说成销量或成功率排名。

### 5.1 候选发现包

- 明确的消费者问题或工作流；
- 目标人群、成人/儿童边界和产品形态；
- 至少一个非社交的需求线索；
- 明显否决风险的初筛。

### 5.2 候选筛选包

- 明确用途、规格和价格带；
- Amazon browse node 或明确标记未确认；
- 优先取得同用途、相近价格带的 Amazon ASIN作参照，可从2个起步；只有一个直接参照时可加入功能替代品，注明差异，数量不作为商业推荐门槛；
- 市场研究不要求供应来源；进入 C 样品筛选再核对具体供货；
- 至少 1 个竞争或价格壁垒信号；
- 至少 1 个消费者失败主题来源或显式缺口；
- 适用时至少 1 个合规/IP 记录；
- 所有关键引用进入证据账本。

进入深筛时，可从 5–10 个代表 ASIN 起步，按细分覆盖与信息价值调整；数量不是通用通过门槛。比较时保留样本版本及纳入/排除理由，避免为迎合结论替换样本。

### 5.3 样品筛选包

- 稳定 offer ID、链接和具体 SKU；
- 页面价、MOQ、材料、结构和可见重尺；
- 页面能回答的字段先从页面取得；
- 只有会改变买样决定的缺口才联系供应商；
- 评论失败主题已经转成样品测试项。

### 5.4 采购与单位经济包

- 样品测试结果；
- 用户最终销售包装实测重尺；
- 对应数量的正式 RFQ、MOQ 和交期；
- Amazon Revenue Calculator 或其他官方费用；
- 头程、广告、退货、损耗、税费和汇率输入；
- 悲观、基准、乐观三情景计算；
- 硬门槛脚本输出。

## 6. 证据三角验证

平台数量不是证据数量。研究按信号生成机制组织：

| 证据家族 | 主要用途 | 不能单独证明 |
| --- | --- | --- |
| Amazon 官方或授权数据 | 目标市场需求、竞争、费用、限制 | 新 Listing 一定能复制竞品销量 |
| 监管与标准组织 | 合规、安全和召回 | 商业需求或利润 |
| 有许可的第三方结构化数据 | 估算分布、历史和竞争结构 | Amazon 官方精确值 |
| 社交与社区 | 痛点、场景、消费者语言 | 销量和可盈利性 |
| 搜索与趋势 | 持续性、季节性、主动兴趣 | 交易量 |
| 其他交易平台 | 价格和成交代理 | Amazon US 销量 |
| 1688 与供应商 | 供应可得性、页面条件、RFQ | 最终到岸成本和质量 |
| 物流商与检测机构 | 履约、报价和测试 | 产品需求 |

多个页面若来自同一上游数据，只按一个来源家族计数。来源无法确认独立性时按不独立处理。

## 7. 信息价值排序

每次只选择当前最高价值的下一动作。优先级依次考虑：

1. 是否可能触发决定性 `hard_gate`；
2. 是否可能改变阶段建议；
3. 是否能推翻关键假设；
4. 是否能显著缩小三情景范围；
5. 是否能直接确定下一项低成本动作；
6. 取得成本、时效、来源质量和可逆性。

不为信息价值伪造精确分数。研究简报只需写清“为什么现在查它”和“什么结果会改变决定”。

## 8. 反证优先原则

每个候选都必须主动回答：

- 最可能让它失败的原因是什么？
- 当前证据只是证明“有人买”，还是也支持“当前用户可进入”？
- 低采购价是否只降低试错损失，而没有形成消费者价值？
- 竞争优势是否已经是行业基础属性？
- 最强反对证据会不会改变阶段建议？

没有找到负面信息，不等于风险不存在。

## 9. 确定性与不确定性的边界

必须交给脚本或可复算规则的内容：

- 单位经济与三情景；
- MOQ、交期、现金占用；
- 必填字段和类型；
- 已配置硬门槛；
- 引用与记录一致性。

不得用模型猜测补齐真实售价、成本、费用、尺寸、重量、销量、成功率或供应商报价。允许明确标为假设的区间和情景计算，不得冒充实测、真实报价或已实现结果。缺口对当前动作的影响按第1.2节判断，不因“可能改变建议”便一律保持 `insufficient`。

上述状态限定于缺口影响的对象与阶段：A/B 市场研究缺少成本、工厂或样品时，经济性记为“未评估”，市场建议仍按六维证据形成；E 阶段缺关键成本则单位经济/采购建议为 `insufficient`。

## 10. 决策留痕模型

每个改变后续行动的节点都是决策检查点。至少记录：

- 稳定 checkpoint ID 和时间；
- 当前阶段和触发原因；
- 当时可选方案；
- Agent 建议；
- 用户明确决定或 `pending`；
- 依据、关键未知和接受风险；
- 下一动作、负责人和复盘条件；
- 被替代的旧检查点。

任务日志按时间追加；跨任务总进度只做导航和摘要。历史不静默覆盖。

## 11. 信息充分与停止纪律

研究协议中的“充分”指足够支持当前有边界的建议，不要求市场信息穷尽或消除所有可影响后续结果的假设。可管理未知已转为明确的试验/调整条件、继续补数的价值低于时间和机会成本时，可以交付当前最佳判断，并按协议记录 `criteria_satisfied`。以下情况都不能单独证明信息充分：

- 已经搜索很多网页；
- 报告很长；
- 时间或预算已经用完；
- 用户倾向某个候选；
- 工具暂时不可用；
- 找不到反对证据。

当关键来源不可用时，保留已取得证据，标记缺口和取得路径，进入 `needs_input`、`blocked` 或阶段性 `insufficient`。

## 12. 交付物分层

| 读者 | 交付物 | 内容边界 |
| --- | --- | --- |
| Agent/研究人员 | 研究简报、证据账本、报告、决策日志 | 完整证据、反证、缺口、历史和版本 |
| 用户/决策者 | 对话摘要、阶段报告 | 结论、依据、限制、下一决定 |
| 采购人员 | 采购执行单 | offer、SKU、数量、价格、链接、核对项、收货要求 |
| 供应商 | 已审批文案或 RFQ | 只问会改变当前阶段决定的字段 |
| 物流商 | 同口径 RFQ | 箱规、货物属性、起运地、目的地、费用与合规口径 |

执行交付物必须让没有项目背景的人无需二次解释即可操作。

## 13. 方法论质量护栏

- 不把研究优先级写成采购排序。
- 不把竞品销量写成自己的销量预测。
- 不把样品供应商当作最终量产工厂。
- 不把公开最低价写成本票全包价。
- 不把进入采购队列写成已经下单。
- 不把用户继续研究写成用户接受 Agent 建议。
- 不在内容未冻结时过早制作正式 PDF。
- 不依赖模型记忆恢复任务。
- 不因工具失败让用户重复提供已经明确的上下文。

## 14. 方法论成功标准

一项研究做得好，不以“用户接受推荐”衡量，而以以下结果衡量：

- 关键事实可追溯；
- 候选在同口径下比较；
- 反证和未知项没有被隐藏；
- 计算可以独立复算；
- 用户决定与 Agent 建议分开；
- 中断后可以从文件恢复；
- 下一动作是低成本、可逆且会增加决策信息；
- 上线后真实结果能够回填并复盘原判断。
