## 1. 这套研究支持什么判断

回答“有没有持续需求、谁获得需求、近期进入者如何获得位置、买家为何选择、什么切入值得验证、什么证据会推翻建议”。研究建议写明对象和 A/B 阶段，不等于用户采纳，更不等于买样、采购或发布授权。

两种入口共用一条研究路径：

- 产品名、照片、ASIN 或链接：先确定用户任务、直接竞品与替代品，再界定细分市场。一个链接不能代表整个市场。
- 类目或使用场景：先拆清可比较的需求分支，再初筛。可先列 3–8 个方向，这是执行起点而非覆盖率或硬门槛。

优先恢复已有证据。用户给种子即可开始，不要求预先交齐材料。供应商、工厂、样品、MOQ、采购预算不是市场研究入场资料；后续需要判断经济性时再补对应输入。

### 1.1 数据支撑的专业判断

交付应明确回答“此刻更看好哪个切入、为什么、值得投入到哪一步、什么信号会使建议改变”。将现有数据连成商业解释，比较机会、竞争、时机、投入和试错损失；不以“仍待验证”代替判断，也不把缺少百分之百证明当成观察等待的充分理由。

有合理机会依据且风险可控制时，建议可以是有条件推进限定试验。样本或数据不足会收窄结论范围、影响投入强度，不必取消方向建议；未知的精确规模、最优参数和利润仍如实标明。参照/经验支持的专业推断应标识依据、可迁移理由、最强反证与推翻条件，不伪造销量或成功概率。新增信息价值需与等待、错过窗口和推迟试验的成本比较。

用途、设计、配色、组合、定价位置等经验性建议，可用需求机制、可比商品和专业常识形成明确选择；不要求每个建议都有直接转化/溢价实验，不为每条推断自动新建消费者调研或前置验证。专业解释足够时就给建议，把真正影响投入的少数风险集中说明。不得通过简单删除限定词，把原先未知的事实改成“已证明”。

复杂探索由负责人提出最小多 Agent 分工，用户控制是否启动与范围；已授权范围内分工执行，各自返回来源、推理、反证和建议。综合结论处理实质分歧，不靠多数票。普通研究和简单修改不默认增加 Agent。

## 2. 八步研究路径（A–B 内环）

八步规定分析义务与产物，实际查询可回跳、并行或略过已有充分证据的模块。每次补数先说明它可能改变哪个判断。

| 步骤 | 做什么、必须回答什么 | 最小留痕 | 与外层衔接 |
| --- | --- | --- | --- |
| 1 界定市场 | 谁、什么场景、什么任务；规格、关键词、纳入/排除边界是什么？ | `market-scope-card.md` | A；产品入口也先界定 |
| 2 初筛方向 | 哪些有需求线索、竞争或具体限制，为什么保留或降低优先级？ | 方向比较、排除理由、当前缺口 | A→B 的研究优先级 |
| 3 采集并核对 | 样本怎样选、能否汇总、哪些缺失/重复/异常？ | `source-register.csv`、`market-sample.csv`、原始文件定位 | B 的可比证据 |
| 4 需求与趋势 | 需求稳定、增长、季节性还是近期异常？覆盖谁、什么月份？ | 分布、历史及搜索趋势、事件解释与反证 | B 需求判断 |
| 5 竞争与新品 | 谁占位置；近期进入者的品牌、父体和持续性是否有可参考路径？ | 去重竞争结构、可见新品及低表现对照 | B 进入机会 |
| 6 关键词与买家需求 | 搜索意图、购买理由、现有解法、未满足问题是什么？ | 词簇、排名口径、可回查的同规格评论与假设 | B 切入假设 |
| 7 价格及进入条件 | 同用途/规格价格怎样；切入成立要满足什么；有何反向证据？ | 价格分层、具体准入事项、经济性状态 | B；成本完整才衔接 E |
| 8 标准报告 | 建议、依据、反证、关键未知和下一验证是什么？ | 九章 HTML 主报告、六维判断、来源明细 | B 建议及用户决定分别记录 |

只要求市场研究时在 A/B 完成即可。C/D 为具体供货与实物验证，E 为量产单位经济；F/G 的计划与研究解释可保留在 PickScout，平台写入和实际运营由 auto-amazon 在具体授权下执行。研究结果复用，不在两仓重做一次。

## 3. 取数与证据口径

### 3.1 来源和输入

卖家精灵为优先工具，依据实际权限使用市场分析、竞品、历史、关键词与评论功能。先看已有导出，再给最小补数清单；不要求使用全部功能。无专门工具时可用已有材料、Amazon 可见页面、榜单、评论和官方资料继续，但不得声称完成了无法取得的全量统计。

表格适合汇总、去重和计算；截图适合核对站点、日期窗口、筛选条件、表头、样本数、优惠和异常。截图不完整时只分析可见范围，不补成零或推算完整市场。每条关键结论对应来源 ID/文件、表页/行号或截图位置；原始资料在 `data/`，私有过程与报告在 `artifacts/`。

页面核对还记录配送邮编、页面时间和工具更新时间，多张列表截图保留重叠行帮助核对。初始关键词在取样前发现；深调可从约3–5个相关核心/场景词结合类目榜单扩展，保留头部、普通及弱表现/未知新品。新增样本仍频繁带来新用途、价带或品牌时继续拆分或补取；扩展主要重复且结构稳定时可结束本轮取样，说明未覆盖范围。数量是工作起点，跨方向比较需相近采样方式和窗口。

| 证据性质 | 可以支持什么 | 限制 |
| --- | --- | --- |
| 页面可观察事实 | 当时可见价格、变体、排名、评论原文 | 卖家材质/性能宣传仍是声明；页面不证明真实性能 |
| 第三方估算 | 样本销量、结构、历史信号 | 不是竞品后台订单；插件、网页和导出同上游不算独立来源 |
| 自有实际记录 | 自己的交易、费用、退货或测试 | 限于对应 SKU、批次和周期 |
| 分析推断 | 按已列规则连接证据形成解释 | 列出推理与最强反证 |
| 待验证假设 | 切入需求、产品价值、可能根因 | 说明如何证伪，不能当成结论事实 |

在 Claim 账本沿用 `fact / inference / hypothesis`；其中 `fact` 的原始数据若是工具估算，必须同时标明 `第三方估算`，不因被记录为观察事实而变成真实订单。

### 3.2 样本、父子体与时间

- 记录关键词 TOP、细类 BSR TOP、自选 ASIN、范围扩展各自入口、筛选条件、截断与样本数；称“本次样本估算规模”，不冒充全市场规模。父节点和子节点、重叠类目不直接相加。
- 保留子 ASIN、父 ASIN、商品系列/去重键、销量字段原名和层级。重复父体销量不能逐行累加；跨用途父体单列。价格是子体时，不能与整个父体销量直接计算销售额或价带份额。父体未知保留未知，不猜合并。
- 同父体冲突值先查更新时间、入口和父子归属快照，不直接取最大值或平均。混合父体缺可靠子体销量时，不把全部销量或按变体数平均分摊给本细分。关键词字段0也可能是未达收录阈值，先核对字段含义再当真实零。
- 默认尽量观察最近 12 个完整自然月，可扩展至 24 个月；不足时交付有限判断，不为凑月份停止全部研究。自然月、最近30天、当前未结束月各自记录，不拼接增速。
- 分别记录报告生成日、原始采集日、数据所属月份和当前页面核对日。到今天打开旧文件不等于数据刷新。
- 用今天的头部回看历史，属于当前样本历史；变化 TOP 曲线、固定队列和全市场趋势分开。不得忽略已退出商品的选择偏差。
- 缺失、未收录、N/A 与真正的零分开。异常保留原值、原因与处理，未核实的不判真伪；样本变化保存版本与理由，不为迎合结论换样本。

### 3.3 指标计算及解释

只对口径一致、去重且有完整分母的有效记录计算，保存公式、输入位置、排除数和代码/表格。未取得分母就不输出集中度或比率。

| 指标 | 定义与使用边界 |
| --- | --- |
| 样本估算总销量/中位数 | 按可比较商品系列去重后汇总/取中位数；说明有效样本与缺失，不当作全市场规模或自己预测 |
| 品牌 CR3 | 样本前三品牌估算销量之和 ÷ 同口径有效样本总量；品牌缺失时说明无法归属部分 |
| 产品 CR10 | 去重后的前十商品系列估算销量之和 ÷ 同口径有效样本总量；不能按多个子体重复计算。样本不足10个时改报Top1/Top3及样本数，不用CR10判断集中程度 |
| 季节集中度 | 同一关键词完整年度搜索量最高3个月合计 ÷ 该年度总搜索量；缺完整年度不算，不设跨类目通过线 |
| 可见新品样本销量占比 | 符合已定义观察窗与日期含义的新品销量 ÷ 同范围有效样本总销量；限定样本和父子层级，不当成功率 |
| 评论主题提及率 | 去重后提及主题的评论数 ÷ 实际分析评论数；保留抽样/星级/时间/规格，一条可多主题，合计可超过100% |
| 同比/环比 | 同比对上年同月，环比对上月；样本与时间须可比，基期为零或缺失不输出无意义百分比 |
| 搜索量 | 搜索次数，不是独立买家人数；重叠词簇不直接加为总需求 |
| BSR/位置 | 类目销售排名、自然搜索位置、广告位置分开；保留站点、节点、时间与来源 |
| 关键词购买率/反查 | 字段含义按当期官方说明核对；搜索次数分母不同于广告点击转化率；反查曝光不等于全部访客或真实成交词 |
| PPC、SPR、标题密度、供需指数 | 辅助线索，不能单独证明实际获客成本、转化或成功概率 |

本规范不保存无法核实的官方引文。具体功能定义、平台规则和费用在实际研究时核对当期官方资料，记录链接与日期。

### 3.4 新品与买家需求

新品先看近 180 天记录上架者，必要时扩到 365 天；这是可调整的观察窗。区分新 ASIN、新父体、新品牌、新卖家，核对日期含义、旧链接改版、变体合并、共享评价和品牌背景。

新品证据递进：能识别新品 → 多个完整月有销售迹象 → 多个可比独立案例支持某条进入路径值得验证。单个单月突出只记为待核案例。只看到搜索/热销新品时，标题写“可见新品表现”，没有全部尝试者与失败者分母就不能计算新品成功率。

评论保留评论 ID/URL、日期、ASIN、父体、评论所指规格/变体、已购/Vine 等可见标记及原文定位。读正面、负面和近期相反体验；跨 ASIN 共享评论先去重。子 ASIN 导出不保证评论属于该子体。缺规格的分组列示，不并入同规格计数。

主题注明分析条数、提及数、独立商品数和抽样方法。AI 主题先回查关键原文，分层/目的性样本的提及比例不能称投诉率、退货率。区分缺陷、误选规格、说明不清、配送损坏、场景不适及预期错配。用户任务→现有解法→反复问题→改进假设→可感知价值→验证动作逐项有据；痛点存在不自动证明可制造或愿付溢价。

### 3.5 价格与经济性

按用途、材质、尺寸/容量、件数、品牌、渠道、变体与促销条件分层。保留标价/券后价、优惠资格与采集日；单件与套装不直接平均。跨价带父体没有子体销量时，不把父体全部销量归给一个价带。高价品牌仅是对应档次参照。

同用途同规格且数据足够时报告价格中位数及四分位区间；只有可比规格才比较单位价。分别看商品、品牌、卖家结构及Amazon自营/第三方分布，三类集中度不混用；内容质量与销量并存不直接证明因果。平台进入条件可用“已核实满足/存在明确限制/待核实/不适用”说明，不凭前台在售认定自己的账号可售。

经济性单列 `未评估 / 情景测算 / 有来源计算`。市场研究缺成本时写“未评估”，市场判断可继续；不使用固定利润率、佣金率或评论数阈值自动决策。确需经济判断且输入适用、完整、有来源时，运行 `scripts/unit_economics.py` 和适用的 `scripts/hard_gates.py`；缺口只限制相应经济或采购判断，不改写市场证据。

## 4. 六维判断和建议

| 维度 | 必须回答 |
| --- | --- |
| 需求持续性 | 稳定、增长、季节性还是事件驱动，需求分布如何？ |
| 可解释进入机会 | 谁占位置，近期可比进入者怎样获得位置，是否可参考？ |
| 具体需求缺口 | 谁在何种场景受影响，现有方案是否已解决？ |
| 流量条件 | 哪些词簇表达该需求，竞争页面与切入方向是否匹配？ |
| 产品与价格结构 | 同用途规格的价值与价格是否支持切入假设？ |
| 明确进入限制 | 有无具体平台、法律、安全/IP或用户禁区，依据与适用阶段是什么？ |

每维写 `支持 / 存在分歧 / 反对 / 未知`，附支持、反证、来源与判断条件；模块证据程度用 `证据充分 / 部分充分 / 不足` 并说明理由。不默认求总分，不以固定销量、利润、集中度、评论数抵消关键未知。

六维结论收敛到一个有条件的 A/B 建议：`advance`（优先下一步研究验证）、`observe`（有条件关注）、`insufficient`（暂缓当前判断）、`reject`（不建议当前切入）。对应的是当前研究对象与下一步，不是样品或采购通过；若报告同时提到其他阶段，分别写状态。用户采纳、外部授权和执行另记。

综合建议必须增加商业取舍：为何优先此方向而非其他选项、哪些未知可在小步试验中解决、当前投入强度、何时调整或停止。`observe` 要说明等待什么以及为何等待比立即试验更值；`insufficient` 只针对无法合理支持或控制风险的具体动作，不因某维标“未知”而机械否定整体。意见明确和证据有限可以同时成立。

统计排名与商业推荐顺序分开：前者按同口径指标计算，后者按需求、竞争、成本、时机和用户条件作取舍。统计条件不足只限制对应统计结论，不以固定ASIN数量禁止推荐先后；用“更推荐”表达专业选择，不冒充销量榜单或成功率排名。

## 5. 九章报告与交付

默认一份连续可读的本地 HTML 主报告，首页先给结论；表格、截图、来源账本作附件。已有主报告按版本迭代，不为每个模块另建孤立主报告。用户明确要求 Excel、PDF 或简短比较时按要求交付，完整研究的九章可缩写但须注明覆盖和未适用项。

| 章 | 内容 |
| --- | --- |
| 1 一页决策摘要 | 研究什么、建议、核心依据、最强反证、还缺什么、下一验证；类目任务加细分方向比较和优先级 |
| 2 调研范围与数据 | 口径卡、样本入口/数、去重前后数量、时间窗、来源、限制 |
| 3 需求与趋势 | 样本量级、分布、可比历史、搜索、季节与异常 |
| 4 细分与价格结构 | 用户任务、规格、材质、组合和价格分层 |
| 5 竞争与新品 | 品牌/商品集中度、评价积累、可见新品路径与低表现对照 |
| 6 关键词与流量 | 意图词簇、曝光/位置口径、页面竞争与切入条件 |
| 7 买家需求与差异化 | 同规格评论、已解决/未解决、价值假设与反证 |
| 8 结论与验证计划 | 六维判断、证据程度、成立/推翻条件、进入限制、经济性状态、最小补数与后续责任 |
| 9 证据附录 | 文件、字段、公式、去重规则、网页链接、采集日期及冲突处理 |

## 6. 完成、补证和权限

按研究协议对当前对象与阶段审计。当前建议有可追溯依据、专业解释、适用限制/反证及可执行下一步时可以交付；不要求消除所有可能影响未来结果的未知。口径冲突、样本层级或来源缺口会阻止其不能支持的精确/强结论，但仍可形成收窄范围的倾向及试验建议。足以阻断当前动作的缺口先作最小补证；未来采购资料不列作当前阻塞。继续搜集若难以改变当前可逆动作，应交付判断、开始下一轮学习，而非反复扩样。

客户报告应能独立解释研究产品、使用者、证据和建议，不写对话争论或修订找补。经用户授权的客户视角审查只读成稿及必要原件，同时检查事实准确、专业取舍和客户能否行动；具体关注点见[协作约定](selection-team.md)。只提出影响理解或行动的问题，修订记录留内部，不以增加谨慎措辞、要求更多资料或通过格式检查代替客户可用性。

研究简报保留一个当前结论区；旧结论和版本过程移入决策日志或历史简报。该区指向当前有效报告/清单，建议与用户决定分别写，恢复时不从多段旧“当前”中猜测。

已授权的只读研究、现有材料分析和本地报告继续执行。新增付费、外部联系、采购、平台写入、公开发布按具体授权执行；同一授权不重复索取。研究数据交接到运营只传范围/版本、候选及证据、未评估项、用户决定和授权状态，运营执行回执再回填研究复盘。

出现新数据、重要价格/新品、定位或规则变化时只更新受影响模块，保留旧版本和原因；一次研究不自动变成定时监控。有权限时可用Product Opportunity Explorer、Brand Analytics等官方数据补证，权限不是开展市场研究的前提。官方资料的取得与当期内容核验分开记录。
